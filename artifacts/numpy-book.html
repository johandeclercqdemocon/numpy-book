Chapter 1 — The array

Build — a function describe(a) that prints the memory layout of any array, and a measurement of how much faster an array sum is than a list sum.

Theory kept — an array is one block of memory plus three numbers per axis: the shape, the dtype and the strides. Nothing else.

Source — New. The behavior is from the NumPy documentation for numpy.ndarray. Every number is from this book's code.

Run this first — uv run python -m examples.ch01_array, which is examples/ch01_array.py.

A NumPy array is a block of memory and a description of how to read it. The block holds raw values, side by side, with no gaps. The description tells NumPy where one row ends and the next row starts. When you know these two facts, most of NumPy is no surprise.

This chapter shows the description, measures what it buys, and shows one case where it buys nothing. Each function that the chapter uses has its printed signature and a parameter table at the place where it first appears. The section How it works shows where each number in the description comes from.

The description: shape, dtype, strides

An array has three attributes that fix its layout.

  • shape is a tuple with the length of each axis.
  • dtype is the type of each value. It fixes the size of one value in bytes, which is itemsize.
  • strides is a tuple with the number of bytes to jump to move one step along each axis.

Build a 2-by-3 array of integers from a nested list, and print the attributes. The values are not 0, 1, 2 and so on, so that you can tell a value from a position.

import numpy as np

a = np.array([[3, 1, 4],
              [1, 5, 9]])
print(a)
print("shape   ", a.shape)
print("dtype   ", a.dtype)
print("itemsize", a.itemsize)
print("strides ", a.strides)
print("nbytes  ", a.nbytes)

[[3 1 4]
 [1 5 9]]
shape    (2, 3)
dtype    int64
itemsize 8
strides  (24, 8)
nbytes   48

Read the strides as a rule. NumPy chose int64, the default integer type on this machine, so each value uses 8 bytes. To move one column to the right, jump 8 bytes, which is one value. To move one row down, jump 24 bytes, which is 3 values of 8 bytes. The array has 6 values of 8 bytes each, so nbytes is 48.

The address of the value at row i and column j is therefore the start of the block plus i * 24 + j * 8. There is no other rule. Slicing, transposing and reshaping all work the same way. They change these numbers and do not touch the block.

The owns field is True when the array owns its block. It is False when the array only looks at the block of another array. The first line shows an array that owns its block. The transpose and the slice read the block of a, so their owns is False. The slice a[:, ::2] takes every second column. It has strides (24, 16), so it reads the same block with a step of 16 bytes.

The last line shows a case that you can find surprising. The call np.arange(6) made the block, and reshape returned a new view of that block. The result owns nothing, and the block belongs to an array that no name points to. A chain such as np.arange(12).reshape(3, 4) makes this case, so you will meet it. Chapter 3 shows why it matters.

Why a sum over an array is fast

A Python list holds pointers. Each pointer leads to a separate integer object somewhere in memory. A sum over the list must follow each pointer, check the type of the object, and add. An array holds the values themselves, so a sum is one tight loop over consecutive bytes.

(This describes the CPython object model. The blocks below measure the time and the memory that follow from it. They do not inspect the interpreter. Appendix A lists this statement.)

Measure both. The code below sums one million integers in each form and keeps the best of five runs.

import timeit

import numpy as np

n = 1_000_000
as_list = list(range(n))
as_array = np.arange(n)

t_list = min(timeit.repeat(lambda: sum(as_list), number=5, repeat=5)) / 5
t_array = min(timeit.repeat(lambda: as_array.sum(), number=5, repeat=5)) / 5
ratio = t_list / t_array
assert sum(as_list) == int(as_array.sum())
assert ratio > 5, "chapter 1 claims an array sum is at least 5 times faster"
print(f"list sum   {t_list * 1e3:8.3f} ms")
print(f"array sum  {t_array * 1e3:8.3f} ms")
print(f"ratio      {ratio:8.1f}x")

# output varies
list sum      9.604 ms
array sum     0.287 ms
ratio          33.4x

The numbers above are from one run on a shared machine. Yours will differ. The assert is the claim: the array sum is at least 5 times faster. The assert fails if the ratio falls below 5 on your machine.

A case where the array is slower

The array has a fixed cost for each call. NumPy must check the type, allocate a result and start the loop. For a very small input, this cost is larger than the work.

import timeit

import numpy as np

small_list = [1, 2, 3]
small_array = np.array(small_list)
t_list = min(timeit.repeat(lambda: sum(small_list), number=20000, repeat=5)) / 20000
t_array = min(timeit.repeat(lambda: small_array.sum(), number=20000, repeat=5)) / 20000
print("array is slower for 3 values:", t_array > t_list)
assert t_array > t_list

array is slower for 3 values: True

The list wins for three values. Use NumPy when you have thousands of values or more, or when the shape of the problem is a table. For a handful of numbers, use a list and do not apologize.

How it works

Everything above follows from one fact: the array is a block of bytes and three attributes that say how to read it. This section opens the block and checks each claim against the bytes.

An array of four 16-bit integers is eight bytes in a row. The block uses 16-bit integers only to keep the output short. One value is above 255, so you can see how a value fills two bytes.

import numpy as np

a = np.array([1, 2, 3, 300], dtype=np.int16)
print(a.tobytes())
print(list(a.tobytes()))

b'\x01\x00\x02\x00\x03\x00,\x01'
[1, 0, 2, 0, 3, 0, 44, 1]

Each integer uses two bytes, and the low byte comes first. The value 300 is 44 + 1 × 256, so its bytes are 44 and then 1. This is the little-endian order of most computers. The block has no header, no length and no type. The array object holds those facts separately, and strides is how it finds a value in the block.

The rule for the address is general. For the index (i0, i1, ..., ik), the byte offset is the sum of i_n * strides[n]. The next block tests this rule on a 3-axis array of 24 integers. It reads every value from the raw bytes with the formula, and compares it with the value that NumPy returns.

import itertools

import numpy as np

a = np.array([[[3, 1, 4, 1], [5, 9, 2, 6], [5, 3, 5, 8]],
              [[9, 7, 9, 3], [2, 3, 8, 4], [6, 2, 6, 4]]])
raw = a.tobytes()


def read_at(index):
    offset = sum(i * s for i, s in zip(index, a.strides))
    return int.from_bytes(raw[offset:offset + a.itemsize], "little", signed=True)


every = list(itertools.product(*[range(n) for n in a.shape]))
print("strides:", a.strides)
print("values checked:", len(every))
print("all equal:", all(read_at(ix) == a[ix] for ix in every))

strides: (96, 32, 8)
values checked: 24
all equal: True

The strides come from the shape. The last axis has stride 8, which is the item size. Each earlier stride is the next stride times the next length: 8 × 4 = 32, and 32 × 3 = 96. This is C order, also called row-major order. In C order, the last axis changes fastest in memory.

The other common order is Fortran order, or column-major order. The first axis changes fastest. NumPy can hold the same values in either order, and only the strides differ. The function np.asfortranarray returns a copy in Fortran order. The function np.array_equal tests that two arrays have the same shape and the same values.

import numpy as np

c = np.array([[[3, 1, 4, 1], [5, 9, 2, 6], [5, 3, 5, 8]],
              [[9, 7, 9, 3], [2, 3, 8, 4], [6, 2, 6, 4]]])
f = np.asfortranarray(c)

print("C strides:", c.strides, "C-contiguous:", c.flags.c_contiguous)
print("F strides:", f.strides, "F-contiguous:", f.flags.f_contiguous)
print("same values:", np.array_equal(c, f))
print("same memory:", np.shares_memory(c, f))

C strides: (96, 32, 8) C-contiguous: True
F strides: (8, 16, 48) F-contiguous: True
same values: True
same memory: False

The Fortran strides (8, 16, 48) run the other way: 8, then 8 × 2 = 16, then 16 × 3 = 48. The two arrays hold equal values in two blocks, so asfortranarray made a copy.

The invariant. The byte offset of an element is always the sum of index times stride, for any shape, any order and any view. A test of this is the block above.

The failure. Code can assume a C-ordered block and receive another order. It then reads the right values slowly. Or it passes a wrong pointer to a library that expects one order. Chapter 3 measures the slow case. The default order is C.

Chapter 2 — Dtypes, and the answers that change silently

Build — checked_add(a, b), an integer add that raises an error when a result does not fit the dtype, in place of wrapping around.

Theory kept — a dtype fixes how many bits a value has. NumPy does not check that a result fits in those bits. It keeps the bits that fit and drops the rest.

Chapter 1 gave every array a dtype. This chapter shows what the dtype does to your numbers. Four things go wrong in practice.

  • Integers wrap.
  • Floats lose small additions.
  • A sum uses a different dtype than its input.
  • A mixed expression picks a dtype that you did not choose.

Each one gives a wrong answer and no error.

Integers wrap around

The function you build

The rule for a safe add is short. Do the add in a wider type. Compare each result with the limits of the narrow type. Raise an error if one result is outside the limits. np.iinfo gives the limits.

import numpy as np


def checked_add(a: np.ndarray, b: np.ndarray) -> np.ndarray:
    """Add two integer arrays. Raise OverflowError if a result does not fit the dtype of `a`."""
    if a.dtype.kind not in "iu" or b.dtype.kind not in "iu":
        raise TypeError("checked_add takes integer arrays only")
    if a.dtype == np.uint64 or b.dtype == np.uint64:
        raise TypeError("uint64 has no wider integer type to check against")
    wide = a.astype(np.int64) + b.astype(np.int64)
    info = np.iinfo(a.dtype)
    if wide.size and (wide.min() < info.min or wide.max() > info.max):
        bad = int(np.flatnonzero((wide < info.min) | (wide > info.max))[0])
        raise OverflowError(f"element {bad}: {int(wide.flat[bad])} does not fit {a.dtype}")
    return wide.astype(a.dtype)


pixels = np.array([200, 250, 10], dtype=np.uint8)
try:
    checked_add(pixels, np.array([100, 100, 100], dtype=np.uint8))
except OverflowError as e:
    print("refused:", e)
print(checked_add(pixels, np.array([10, 5, 100], dtype=np.uint8)))

How it works

Two facts explain every surprise in this chapter. An integer dtype does arithmetic modulo a power of 2. A float dtype stores a sign, an exponent and a fixed number of fraction bits.

Integers. An int8 has 8 bits, and the add of two int8 values keeps the low 8 bits of the result. This is arithmetic modulo 256. The bits are read as a signed number, in two's complement form. The rule

Basic slicing makes a view. Indexing with a list of integers or with a boolean mask makes a copy.

import numpy as np

a = np.array([[3, 1, 4, 1],
              [5, 9, 2, 6],
              [5, 3, 5, 8]])

print("list   shares memory:", np.shares_memory(a, fancy))
print("mask   shares memory:", np.shares_memory(a, masked))

slice  shares memory: True
list   shares memory: False
mask   shares memory: False

The reason is the strides from chapter 1. A slice is always a regular pattern, so one set of strides can describe it. A list of integers or a mask can pick any elements in any order, and no set of strides can describe that. NumPy must make a new block.

A write through a view changes the original.

import numpy as np

[ 3 -1  4  1]

The value at a[0, 1] is now −1, although the code never wrote to a.

The function you build

The .base attribute of a view points to the array that owns the block. NumPy sets it to the owner directly, even for a view of a view, so one step is enough. The loop below follows the chain to its end anyway. A block can belong to an object that is not an array, such as bytes.

import numpy as np


def root(a: np.ndarray) -> np.ndarray:
    """Follow .base links to the array that owns the memory of `a`."""
    while isinstance(a.base, np.ndarray):
        a = a.base
    return a

Trap 1: a write to a copy is lost

A mask on the left of = writes into the array. A mask on the right makes a copy, and a write into the copy is lost.

Trap 4: the shape of a mixed index

When you mix a slice and an index list in one index, NumPy can move the axes of the result.

Read the first line. The index picks A[0] and then columns 0 and 1, and you can expect the shape (3, 2). The result is (2, 3). The rule is that the axes that come from index lists go first when a slice separates two advanced indices. In the first line the scalar 0 and the list [0, 1] are both advanced indices, and the slice sits between them.

The third line avoids the problem. It indexes in two steps, and the shape is (3, 2). When the shape of a mixed index matters, use two steps or print .shape before you rely on it.

The function you build

A group-by sum is the most common use of a repeated index. You have one value per row and one key per row, and you want one total per key. Three versions follow. They must give the same answer.

import numpy as np


def group_sum_loop(keys: np.ndarray, values: np.ndarray, k: int) -> np.ndarray:
    """Add up `values` for each key in 0..k-1 with a Python loop."""
    out = [0.0] * k
    for key, v in zip(keys.tolist(), values.tolist()):
        out[key] += v
    return np.array(out)


def group_sum_at(keys: np.ndarray, values: np.ndarray, k: int) -> np.ndarray:
    """Add up `values` for each key in 0..k-1 with np.add.at."""
    out = np.zeros(k)
    np.add.at(out, keys, values)
    return out


def group_sum_bincount(keys: np.ndarray, values: np.ndarray, k: int) -> np.ndarray:
    """Add up `values` for each key in 0..k-1 with np.bincount."""
    return np.bincount(keys, weights=values, minlength=k)

How it works

An index with integer arrays or a mask is a gather. NumPy broadcasts the index arrays against each other. It reads one element for each position of the broadcast shape. It writes the elements into a new array. This explains the four traps, and the next blocks test each part.

Chapter 5 — Broadcasting

Build — three functions that compute all distances between two sets of points, a loop version, a broadcast version and a dot-product version, with a measured memory cost and a measured precision limit for each.

Theory kept — two shapes combine when, from the right, each pair of lengths is equal or one of them is 1. A length of 1 is stretched with a stride of 0, so the stretch costs no memory until an operation writes a result.

Broadcasting is the rule that lets a - b work when a and b have different shapes. It replaces most of the loops that you write in plain Python. It also makes one new mistake easy: a result that is much larger than you meant.

This chapter states the rule, shows the stride trick behind it, and uses it to compute all pairwise distances. The distance example is the right size to show the three costs of a vectorized program: time, memory and precision.

The rule

Write the two shapes one above the other, aligned on the right. For each column, the two lengths must be equal, or one of them must be 1. A missing length on the left counts as 1. The result has the larger length in each column.

print(np.broadcast_shapes((3, 1), (1, 4)))
print(np.broadcast_shapes((8, 1, 6, 1), (7, 1, 5)))
print(np.broadcast_shapes((5, 3), (3,)))

try:
    np.ones(3) + np.ones(4)
except ValueError as e:
    print("error:", e)

(3, 4)
(8, 7, 6, 5)
(5, 3)
error: operands could not be broadcast together with shapes (3,) (4,)

Read the second line with the rule. The shapes (8, 1, 6, 1) and (7, 1, 5) align as columns 8 1 6 1 over _ 7 1 5. The columns pair as 1 with 5, 6 with 1, 1 with 7, and 8 with nothing. The result is (8, 7, 6, 5). The last line shows what happens when two lengths differ and neither is 1.

The function you build

Given A with n points and B with m points, in d dimensions, build the (n, m) matrix of distances. Three versions follow.

import numpy as np


def dist_loop(A: np.ndarray, B: np.ndarray) -> np.ndarray:
    """Distances between every row of A and every row of B, with two Python loops."""
    out = np.empty((len(A), len(B)))
    for i, a in enumerate(A):
        for j, b in enumerate(B):
            out[i, j] = np.sqrt(((a - b) ** 2).sum())
    return out


def dist_broadcast(A: np.ndarray, B: np.ndarray) -> np.ndarray:
    """Exact. Builds an (n, m, d) temporary array."""
    return np.sqrt(((A[:, None, :] - B[None, :, :]) ** 2).sum(-1))


def dist_dot(A: np.ndarray, B: np.ndarray) -> np.ndarray:
    """Fast and small, but loses precision when points are close together and far from the origin."""
    d2 = (A ** 2).sum(1)[:, None] + (B ** 2).sum(1)[None, :] - 2 * A @ B.T
    return np.sqrt(np.maximum(d2, 0))

The broadcast version is the same formula as the loop, with A[:, None, :] of shape (n, 1, d) and B[None, :, :] of shape (1, m, d). It subtracts to (n, m, d), squares, and sums over the last axis. The dot version uses the identity that the squared distance is |a|² + |b|² − 2 a·b. The cross term A @ B.T is one matrix product.

On this well-behaved input, all three agree. The dot version differs from the loop by about 3e-15, which is the rounding of float64.

How it works

The rule is a small algorithm. Align the shapes on the right, and for each position take the one length that is not 1. If two lengths differ and neither is 1, stop with an error. The next block writes it in ten lines, and tests it against np.broadcast_shapes on 2000 random pairs of shapes.

import numpy as np


def broadcast_shape(*shapes):
    """The broadcast rule written out: right-aligned, equal or 1."""
    n = max(len(s) for s in shapes)
    padded = [(1,) * (n - len(s)) + tuple(s) for s in shapes]
    out = []
    for lengths in zip(*padded):
        not_one = {length for length in lengths if length != 1}
        if len(not_one) > 1:
            raise ValueError(f"lengths {sorted(not_one)} cannot broadcast")
        out.append(not_one.pop() if not_one else 1)
    return tuple(out)


rng = np.random.default_rng(0)
agree = valid = 0
for _ in range(2000):
    shapes = [tuple(int(x) for x in rng.choice([1, 2, 3], size=rng.integers(0, 4))) for _ in range(2)]
    try:
        want = np.broadcast_shapes(*shapes)
    except ValueError:
        want = None
    try:
        got = broadcast_shape(*shapes)
    except ValueError:
        got = None
    agree += got == want
    valid += want is not None

print("pairs tested:       ", 2000)
print("pairs that broadcast:", valid)
print("pairs that agree:    ", agree)

The invariant. The shape of the result is the right-aligned maximum of the input shapes, and the rule makes no copy of the inputs. The block above tests the rule against NumPy on 2000 cases.

The failure. A shape that is almost right passes. A (n,) against an (n, 1) is allowed, and the result is (n, n). The error comes only when two lengths differ and neither is 1. Test the shape of a result, because the rule cannot know what you meant.

Theory kept — a ufunc is a function that runs element by element in compiled code. It has methods (reduce, accumulate, outer) that apply it along an axis. Vectorization is the act of rewriting a loop as calls to ufuncs. It does not exist for every loop.

A ufunc, short for universal function, is the unit of speed in NumPy. np.add, np.multiply, np.sqrt, np.maximum and 102 others are ufuncs. The section How it works counts them. Temporaries and out=

An expression such as a * b + c makes a temporary array for a * b, and then a second array for the sum. For small arrays this does not matter. For large arrays, each temporary is a pass over memory and an allocation. Writing into a result array that you made in advance avoids both.

The function you build: a moving average

A moving average of window w replaces each value with the mean of the w values that end there. The loop version is the definition. Three others follow.

import numpy as np
from numpy.lib.stride_tricks import sliding_window_view


def ma_loop(x: np.ndarray, w: int) -> np.ndarray:
    """Moving average of window w, from the definition."""
    out = np.empty(len(x) - w + 1)
    for i in range(len(out)):
        out[i] = x[i:i + w].mean()
    return out


def ma_cumsum(x: np.ndarray, w: int) -> np.ndarray:
    """Moving average from a cumulative sum."""
    c = np.concatenate([[0.0], np.cumsum(x)])
    return (c[w:] - c[:-w]) / w


def ma_window(x: np.ndarray, w: int) -> np.ndarray:
    """Moving average from a sliding-window view."""
    return sliding_window_view(x, w).mean(axis=-1)


def ma_convolve(x: np.ndarray, w: int) -> np.ndarray:
    """Moving average as a convolution with a flat kernel."""
    return np.convolve(x, np.ones(w) / w, mode="valid")


x = np.random.default_rng(2).random(20_000)
ref = ma_loop(x, 50)
for f in (ma_cumsum, ma_window, ma_convolve):

When no vectorized form exists

Some loops cannot be written with ufuncs. The usual cause is a dependency: each value needs the result for the previous value. An exponential moving average is the standard case.

import time

import numpy as np


def ema_loop(x, alpha):
    out = np.empty_like(x)
    acc = x[0]
    for i, v in enumerate(x.tolist()):
        acc = alpha * v + (1 - alpha) * acc
        out[i] = acc
    return out


x = np.random.default_rng(2).random(1_000_000)

The loop above ran at the rate that the block printed. The plain ufunc methods do not apply to this loop directly, because each step needs the result of the step before it.

How it works

A ufunc is a table of compiled loops, one for each combination of input types. When you call it, NumPy finds the first loop in the table to which both inputs can be cast safely. It then runs that loop over the whole array. (The NumPy documentation describes this rule. This book did not measure the buffers that the cast uses.) The type letters are the names of the dtype: b is int8, f is float32, d is float64.

Solve, do not invert

A rule of thumb is that the error of the answer is about cond(A) times the rounding unit of float64, which is 1.1e-16. For n = 8, that is 1.5e10 times 1.1e-16, or about 2e-6. The table shows 1.2e-7 for solve, and 1.9e-6 for inv. The rule gives the order of magnitude.

For n = 12 the condition number is 1.8e16, which is more than the number of digits that float64 has. No method can give a good answer. Both are wrong, and the errors are 0.7 and 21.

The last two columns show the real difference. The residual H @ x - b of solve is at the rounding level for every n, even when x is wrong. The residual of inv is 6e7 times larger at n = 8 and 1e14 times larger at n = 12. The inverse method gives an answer that does not even satisfy the equation. Use the residual as a check: it tells you if the method did its job, where the error tells you only that the problem was hard.

Fit with lstsq, not with the normal equations

What the documentation promises, and what it does not

The numbers above are stable on one version of NumPy. The NumPy policy is that the streams of Generator methods are not guaranteed to be the same between versions. A seed makes a run reproducible on one installation. It does not make it reproducible for ever.

If a published number depends on a stream, write the NumPy version next to the seed. This book does so. NumPy 2.5.4 produced every output.

The function you build

A line fit gives one slope. To say how well the data fix the slope, resample the rows with replacement, fit again, and look at the spread of the slopes. This is the bootstrap. Doing 1000 fits is a loop in Python, and a few lines of broadcasting here.

import numpy as np


def bootstrap_slopes(x: np.ndarray, y: np.ndarray, n_boot: int, seed) -> np.ndarray:
    """Slope of the least-squares line for `n_boot` resamples of the rows, all at once."""
    g = np.random.default_rng(seed)
    idx = g.integers(0, len(x), (n_boot, len(x)))
    xs, ys = x[idx], y[idx]
    xc = xs - xs.mean(axis=1, keepdims=True)
    yc = ys - ys.mean(axis=1, keepdims=True)
    return (xc * yc).sum(axis=1) / (xc * xc).sum(axis=1)


def fit_line(x: np.ndarray, y: np.ndarray, n_boot: int = 1000, seed=0) -> tuple[float, float, tuple[float, float]]:
    """Return (intercept, slope, (low, high)) with a 95% bootstrap interval for the slope."""
    X = np.column_stack([np.ones_like(x), x])
    (b0, b1), *_ = np.linalg.lstsq(X, y, rcond=None)
    low, high = np.percentile(bootstrap_slopes(x, y, n_boot, seed), [2.5, 97.5])
    return float(b0), float(b1), (float(low), float(high))

How it works

Solve. The function solve does not compute an inverse. It factors the matrix into a lower and an upper triangle with row swaps, which is Gaussian elimination with partial pivoting. It then solves the two triangular systems. The next block writes this in a few lines and compares it with np.linalg.solve.

import numpy as np

from examples.ch07_linalg_random import hilbert


def lu_solve(A, b):
    """Gaussian elimination with partial pivoting, then back substitution."""
    A, b = A.astype(float).copy(), b.astype(float).copy()
    n = len(b)
    for k in range(n):
        p = k + np.argmax(np.abs(A[k:, k]))          # pivot: the largest value in the column
        if p != k:
            A[[k, p]], b[[k, p]] = A[[p, k]], b[[p, k]]
        for i in range(k + 1, n):
            f = A[i, k] / A[k, k]
            A[i, k:] -= f * A[k, k:]
            b[i] -= f * b[k]
    x = np.zeros(n)
    for i in range(n - 1, -1, -1):
        x[i] = (b[i] - A[i, i + 1:] @ x[i + 1:]) / A[i, i]
    return x

The algorithm in two lines

Start with k centroids. Repeat two steps until the labels stop changing. First, give each point the label of its nearest centroid. Second, move each centroid to the mean of the points that have its label.

The first step is a distance matrix and an argmin. The second step is a group-by sum divided by a count. Both are in the book already.

The function you build

import numpy as np

from examples.ch05_broadcasting import dist_dot_centered      # chapter 5


def kmeans(X: np.ndarray, k: int, seed: int = 0, max_iter: int = 100) -> tuple[np.ndarray, np.ndarray, int]:
    """Lloyd's algorithm. Returns (centroids, labels, iterations)."""
    g = np.random.default_rng(seed)                           # chapter 7
    C = X[g.choice(len(X), k, replace=False)].copy()          # chapter 3: copy, not a view
    labels = np.full(len(X), -1)
    for it in range(1, max_iter + 1):
        new_labels = dist_dot_centered(X, C).argmin(axis=1)   # chapter 5
        if np.array_equal(new_labels, labels):
            return C, labels, it - 1
        labels = new_labels
        sums = np.zeros_like(C)
        np.add.at(sums, labels, X)                            # chapter 4
        counts = np.bincount(labels, minlength=k)
        keep = counts > 0                                     # an empty cluster keeps its centroid
        C[keep] = sums[keep] / counts[keep, None]             # chapter 5: broadcast a column
    return C, labels, max_iter

In 6 of 30 runs, the algorithm stops at a purity of 0.67. The loop version agrees with the vectorized version on seed 1, so the cause is not a bug in the NumPy code. No single step improves this result. It is a local minimum.

Each run has an inertia, which is the sum of squared distances from the points to their centroids. The good runs all have the same inertia, and every failed run has a larger one. How it works

Each iteration of kmeans is a chain of five steps, and every step has a shape. The next block runs one iteration by hand on the data of this chapter, and prints the shape of every value.

The distance step has the cost n * k * d multiplications, and the group sum has the cost n * d additions. Both are linear in the number of points. The loop over iterations has few steps, so the total cost is linear in n.

The reason that the algorithm works is one fact. Each of the two steps does not make the inertia larger. The label step gives each point the nearest centroid. The mean step puts each centroid at the point that minimizes the squared distances of its cluster. The next block records the inertia after every label step for 30 seeds, and tests that it never rises.

import numpy as np

from examples.ch05_broadcasting import dist_dot_centered
from examples.ch08_kmeans import inertia, make_blobs

centers = np.array([[0.0, 0.0], [6.0, 0.0], [3.0, 5.0]])
X, _ = make_blobs(300, centers, 0.8, seed=1)
k = 3

never_rises, iterations = 0, []
for seed in range(30):
    C = X[np.random.default_rng(seed).choice(len(X), k, replace=False)].copy()
    history = []
    for _ in range(100):
        labels = dist_dot_centered(X, C).argmin(axis=1)
        history.append(inertia(X, C, labels))
        sums = np.zeros_like(C)
        np.add.at(sums, labels, X)
        counts = np.bincount(labels, minlength=k)
        keep = counts > 0
        C[keep] = sums[keep] / counts[keep, None]
        if len(history) > 1 and np.isclose(history[-1], history[-2], rtol=0, atol=1e-9):
            break
    never_rises += all(b <= a + 1e-9 for a, b in zip(history, history[1:]))
    iterations.append(len(history))

print("seeds where the inertia never rose:", never_rises, "of 30")
print("iterations until it stopped: least", min(iterations), "most", max(iterations))

seeds where the inertia never rose: 30 of 30
iterations until it stopped: least 3 most 19

The invariant. The inertia never rises from one iteration to the next. The block above tests it on 30 starts.

The failure. The invariant says that the algorithm stops, and not that it stops at the best answer. It stops at the first point where no step helps, which is a local minimum. Six of the 30 seeds stop there. Their inertia is 5.3 to 5.5 times the best value, which is 1176.7.

A basic slice is a view. The first kmeans step then writes the new centroids into C, which is the first k rows of X. The input changes, and the three rows that changed are the first three rows of X.

import numpy as np

from examples.ch05_broadcasting import dist_dot_centered
from examples.ch08_kmeans import make_blobs


def kmeans_view(X, k, max_iter=100):
    C = X[:k]                                    # a view: the .copy() is gone
    labels = np.full(len(X), -1)
    for _ in range(max_iter):
        new_labels = dist_dot_centered(X, C).argmin(axis=1)
        if np.array_equal(new_labels, labels):
            break
        labels = new_labels
        sums = np.zeros_like(C)
        np.add.at(sums, labels, X)
        counts = np.bincount(labels, minlength=k)
        keep = counts > 0
        C[keep] = sums[keep] / counts[keep, None]
    return C, labels


centers = np.array([[0.0, 0.0], [6.0, 0.0], [3.0, 5.0]])
X, _ = make_blobs(300, centers, 0.8, seed=1)
before = X.copy()

print("X unchanged:", np.array_equal(X, before))

assert not np.array_equal(X, before)
