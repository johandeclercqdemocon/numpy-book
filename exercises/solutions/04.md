## 1. [measure]

```python
import numpy as np

idx = np.array([0, 0, 0, 1, 1, 2])

a = np.zeros(3, dtype=int)
a[idx] += 1
b = np.zeros(3, dtype=int)
np.add.at(b, idx, 1)
print("a[idx] += 1:", a)
print("np.add.at  :", b)
assert a.tolist() == [1, 1, 1]
assert b.tolist() == [3, 2, 1]
```

```text
a[idx] += 1: [1 1 1]
np.add.at  : [3 2 1]
```

Index 0 appears 3 times and index 1 appears 2 times. The statement `a[idx] += 1` reads `a[idx]` once, so each position gets only one update.

## 2. [break]

`np.errstate(all="raise")` turns every floating-point warning into an exception in its block.

```python
import numpy as np

x = np.array([1.0, 0.0])
with np.errstate(all="raise"):
    try:
        np.where(x > 0, np.log(x), 0)
    except FloatingPointError as e:
        print(type(e).__name__, "-", e)
```

```text
FloatingPointError - divide by zero encountered in log
```

The error comes from `np.log(x)`, which `np.where` receives as an argument. The condition `x > 0` is false for the second element, and it does not stop the log from running. This shows that `np.where` selects among values that are already computed.

## 3. [judge]

**Position.** Do not change the code until a profile of the real data shows that this call is a large part of the run time.

**What a good answer weighs.** The advice is old. It dates from NumPy 1.x, which the book did not test. On 2.5.4 the two are within a factor of 2 for the input of chapter 4. The assert of chapter 4 proves it. The version of the team is the first fact to check.

The key range is the second fact. The function `np.bincount` needs non-negative integers and makes an array as long as the largest key. That is wasteful for sparse keys. The third fact is how much of the run time the call takes. A change that saves 20 percent of 2 percent of the run is not worth a review.

**Strongest objection.** The function `np.bincount` states the intent more directly, and it reads better. This is a fair reason to change. It is a reason about readability, and it needs no speed claim.

**What overturns the position.** A profile that shows the call above 20 percent of the run time overturns it. A measurement on the team's own data and version that shows `bincount` is faster by a useful margin has the same effect.
