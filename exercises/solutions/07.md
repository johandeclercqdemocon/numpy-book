## 2. [break]

The `float32` epsilon is 1.2e-7. The condition number of the 8-by-8 Hilbert matrix is 1.5e10. The product is 1.8e3, which is more than the size of the answer. No digit is guaranteed, and the measured error is of order 1.

```python
import numpy as np

from examples.ch07_linalg_random import hilbert

H = hilbert(8)
b = H @ np.ones(8)
e64 = np.abs(np.linalg.solve(H, b) - 1).max()
e32 = np.abs(np.linalg.solve(H.astype(np.float32), b.astype(np.float32)) - 1).max()
print(f"float64 error: {e64:.1e}")
print(f"float32 error: {e32:.1f}")
assert e64 < 1e-5
assert e32 > 1.0
print("cond * eps32 =", f"{np.linalg.cond(H) * np.finfo(np.float32).eps:.1e}")
```

```text
float64 error: 1.2e-07
float32 error: 6.8
cond * eps32 = 1.8e+03
```

The rule of thumb gives an upper bound and not a prediction. The measured error is 6.8, which is below the bound of 1.8e3 and far above 1.

## 3. [judge]

**Position.** Stop using the global seed. Create one generator in the main script. Pass it to every function that draws numbers.

**What a good answer weighs.** The shared helpers draw from the same global state. A change in one helper changes the numbers in every script that calls it, and nobody sees the link. A passed generator makes the dependency visible in the signature.

The cost is one argument on each function and one decision about who owns the seed. For parallel work, add `SeedSequence.spawn`. No method of seeding promises the same stream across NumPy versions, so each result must also record the version.

**Strongest objection.** Five scripts already work. A change of every signature touches all of them for no visible gain. This is true for the code that exists. The practical answer is to apply the rule to new code and to the helpers that you change anyway.

**What overturns the position.** A search of the helpers for `np.random` calls takes minutes. If no helper draws random numbers, the global seed has no hidden coupling, and the change gives little.
