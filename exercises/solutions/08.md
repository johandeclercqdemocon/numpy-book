## 2. [break]

A basic slice is a view. The first `kmeans` step then writes the new centroids into `C`, which is the first `k` rows of `X`. The input changes, and the three rows that changed are the first three rows of `X`.

```python
import numpy as np

from examples.ch05_broadcasting import dist_dot_centered
from examples.ch08_kmeans import make_blobs


def kmeans_view(X, k, max_iter=100):
    C = X[:k]                                    # a view: the .copy() is gone
    labels = np.full(len(X), -1)
    for _ in range(max_iter):
        new_labels = dist_dot_centered(X, C).argmin(axis=1)
        if np.array_equal(new_labels, labels):
            break
        labels = new_labels
        sums = np.zeros_like(C)
        np.add.at(sums, labels, X)
        counts = np.bincount(labels, minlength=k)
        keep = counts > 0
        C[keep] = sums[keep] / counts[keep, None]
    return C, labels


centers = np.array([[0.0, 0.0], [6.0, 0.0], [3.0, 5.0]])
X, _ = make_blobs(300, centers, 0.8, seed=1)
before = X.copy()
C, labels = kmeans_view(X, 3)
print("C shares memory with X:", np.shares_memory(C, X))
print("X unchanged:", np.array_equal(X, before))
print("rows that changed:", int((X != before).any(axis=1).sum()))
assert not np.array_equal(X, before)
```

```text
C shares memory with X: True
X unchanged: False
rows that changed: 3
```

Chapter 3 predicted this: the rule is that basic slicing makes a view, and a write through a view changes the original. The original `kmeans` uses `X[g.choice(...)]`, an index list, which always makes a copy, so the `.copy()` there is for safety and not for need. The exercise shows what the safety protects against if a later edit changes the index to a slice.

## 3. [judge]

**Position.** Keep best-of-10 until you measure k-means++ on your own data. Then decide with the failure rate and the cost.

**What a good answer weighs.** On the blobs of chapter 8, 6 of 30 single starts fail, and 10 starts remove the failures. The cost is a factor of 10 in time. A smarter initialization spreads the starting centroids and reduces failures. It also costs a pass over the data. Whether it removes the need for restarts depends on the data and on `k`. This book did not measure it.

At 900 points a run takes under a millisecond, so ten starts is cheap. At 300,000 points a start takes 0.3 seconds. Three seconds for ten starts is small for a batch job and large for a request.

**Strongest objection.** Restarts treat a property of the initialization as a statistical problem. A better method removes it at the source. This is correct in principle. It is an argument to implement the better initialization and measure it. It is not a reason to remove the restarts before the measurement.

**What overturns the position.** Measure the better initialization on the real data. Suppose it fails in fewer than 1 run in 100 with a single start. Suppose also that its cost is below that of two plain starts. Then one start is enough.
