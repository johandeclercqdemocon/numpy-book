## 1. [measure]

A `float32` has 24 bits of precision. Below 2²⁴ every integer is exact and has a gap of at most 1 to its neighbor. At 2²⁴ the gap becomes 2, and adding 1 rounds back to the same number.

```python
import numpy as np

n = np.arange(1, 2 ** 24 + 2, dtype=np.float32)        # every integer up to 2**24 + 1
stuck = np.flatnonzero(n + np.float32(1) == n)
smallest = int(n[stuck[0]])
print(smallest)
assert smallest == 2 ** 24 == 16777216
```

```text
16777216
```

The test runs on every integer from 1 to 2²⁴ + 1, so it finds the smallest `n` and not only a power of 2.

## 2. [break]

The argument is `dtype=np.float64`. The cumulative sum then keeps its running total in `float64`, which has digits to spare.

```python
import numpy as np

x = np.full(10_000_000, 0.1, dtype=np.float32)
exact = float(np.float32(0.1)) * x.size

plain = float(np.cumsum(x)[-1])
wide = float(np.cumsum(x, dtype=np.float64)[-1])
print(f"plain cumsum relative error: {abs(plain - exact) / exact:.2e}")
print(f"float64 cumsum relative error: {abs(wide - exact) / exact:.2e}")
assert abs(plain - exact) / exact > 1e-2
assert abs(wide - exact) / exact < 1e-6
```

```text
plain cumsum relative error: 8.79e-02
float64 cumsum relative error: 0.00e+00
```

The input is still `float32`. Only the accumulator changed. The cost is memory: the result of `cumsum` is now 80 MB and not 40 MB.

## 3. [judge]

**Position.** Raise an error by default. Offer a `clip=True` option for the caller that wants saturation. Wrapping is almost never what the caller means.

**What a good answer weighs.** The caller of an image function usually wants a bright pixel to stay bright. That is a clip. A wrapped pixel turns a bright area dark, and the image looks plausible and is wrong. An error stops the program at the first bad input. The cost is one extra comparison pass.

A clip hides that the input was out of range, and that fact can be the information that the caller needs. Wrapping is correct for hash functions and modular counters. These are not images.

**Strongest objection.** In a video pipeline that runs at 60 frames a second, an error stops the stream on one bad frame. For this caller the silent clip is the safe choice. The answer is the option: the default is the error, and the pipeline sets `clip=True`.

**What overturns the position.** A measurement can show that the check costs more than the budget of the caller. An example is 10 percent of the frame time. Then the default must change, and the first line of the documentation must say so.
